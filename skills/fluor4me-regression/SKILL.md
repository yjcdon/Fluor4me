# Fluor4me 功能回归

## 选用例

从现有用例索引选检查，重复项合并。此项目目前有[脚本用例](tests/script/README.md)和[文本用例](tests/text/README.md)。用例按实际验证条件选择执行方式，全用脚本、全文本或混合均可，只为采用的方式建目录。

- **冒烟**走受影响功能最短的成功路径。构建或打包改动跑 `PKG-01`，应用启动行为改动选 `INSTALL-01` 的菜单栏检查。
- **迭代必测**选 `KEY-01`（逐应用切换）、`CHR-01`（F4 访问或搜索）、`CHR-04`（F5 复制标签页）和 `STATE-01`（暂停并恢复）。同轮已有实测且后续改动未影响该行为时可复用。
- **变更点**覆盖本次需求、相关边界和共享调用方。改 Chrome 键盘映射时同时看 F4、F5 和离开 Chrome 后的恢复。改窗口或本地化时检查对应设置和列表。

默认增量测试。用户指定范围时按指定范围执行，明确要求全测时覆盖两份索引中的全部用例和本次变更点。仅改文档时检查编号、命令和链接。

## 判定与分工

1. **先定义正确。** 优先采用本次需求，其余沿用已有通过条件。AI 先用已确认的现有行为、macOS 实际按键结果或 Chrome 原生命令作对照。状态图标和合成事件可作佐证，物理键与系统集成结果按实机记录。
2. **脚本做固定检查。** 优先复用现有工具和脚本。应用包字段、签名、架构和资源可以直接判定。
3. **AI 走真实交互。** 依赖前台窗口、Chrome 配置或系统权限的用例可直接按 Markdown 步骤执行。脚本失败时，先在相同条件下定位第一处差异。修复前后用同一检查，覆盖原触发条件后才确认修复。
4. **用户处理待决事项。** AI 先完成可执行的检查。只能由用户完成的物理按键、系统批准、重新登录或仍有歧义的预期，给出已验证证据和剩余步骤，由用户决定是否补测。

## 准备和记录

- 确认候选的版本、构建号、路径及来源，避免让同一账户的两份 Fluor4me 同时管理键盘。若要替换已在用的实例，先取得用户授权。
- Chrome 行为使用实际安装的 Chrome。获准后优先复用现有浏览器连接，用测试标签页核对数量、地址、历史和窗口归属。按键前确认前台应用、当前窗口和有效选区，和本次同一状态下的原生结果比较。
- 在授权的 Apple Silicon 内置键盘上做物理键验收。辅助功能权限切换、强退、切换登录项、休眠及升级使用授权的隔离账户或专用测试环境。记录系统与 Chrome 版本、键盘型号、初始模式及已有映射，涉及 Chrome 时另记界面语言、普通或无痕模式及配置数量。
- 按编号记录前提、实际结果和证据，标明通过、失败或未验证。分别记录实机、合成事件或只读检查的覆盖范围。条件不足时注明缺项，继续可执行的用例。Chrome 回归用[样本索引](references/chrome-samples.md)。2.6.0 的历史记录可从 `v2.7.0` 标签下的 `docs/2.6.0/测试用例.md` 查阅。

## 清理与维护

- 结束、失败或中断时，关闭本次的窗口、标签页和测试实例，恢复原前台应用、系统键盘模式、映射和本次变更的偏好或授权。复核映射差异时保留原有用户映射，强退用例先完成下一次启动清理。为测试启动的服务或进程记录 PID，结束后停止并确认退出。
- 本次生成的构建副本、日志、截图和临时测试文件移入系统废纸篓。保留仓库用例和可复用样本。
- `tests/script/` 每类功能一个可执行脚本，按需要选择语言。每个测试函数对应一个编号，例如 `test_PKG_01`。`tests/text/` 每类功能一个 Markdown，每条写前提、步骤和预期，README 放索引。更换执行方式或样本时保留原编号。
- 用户明确要求发布时，把本版已实测的新行为及复现样本补入用例库。已有行为更新原条目，补入曾漏测的触发条件。
