# Fluor4me 功能回归

## 测试前

默认增量，从[脚本用例](tests/script/README.md)和[文本用例](tests/text/README.md)选例去重。

- **冒烟**走受影响功能最短的成功路径。构建或打包改动跑 `PKG-01`，应用启动行为改动选 `INSTALL-01` 的菜单栏检查。
- **迭代必测**选 `KEY-01`（逐应用切换）、`CHR-01`（F4 访问或搜索）、`CHR-04`（F5 复制标签页）和 `STATE-01`（暂停并恢复）。同轮已有实测且后续改动未影响该行为时可复用。
- **变更点**覆盖本次需求、相关边界和共享调用方。改 Chrome 键盘映射时同时看 F4、F5 和离开 Chrome 后的恢复。改窗口或本地化时检查对应设置和列表。

按用户指定的范围执行，明确要求全测时覆盖两份索引中的全部用例及本次变更点。仅改文档时检查编号、命令和链接。

以本次需求和已确认行为定义通过条件，用 macOS 实际按键或 Chrome 原生命令作对照。确认候选的版本、构建号、路径及来源，同一账户每次只运行一个管理键盘的实例。替换在用实例前取得用户授权。

物理键验收使用获准的 Apple Silicon 内置键盘。辅助功能权限切换、强退、切换登录项、休眠及升级使用获准的隔离账户或专用环境。Chrome 用装好的浏览器和[样本索引](references/chrome-samples.md)，获准后优先复用现有连接。记录系统、键盘型号、初始模式及已有映射。涉及 Chrome 时另记版本、菜单语言、窗口模式和配置数量。2.6.0 的历史记录见 `v2.7.0` 标签下的 `docs/2.6.0/测试用例.md`。

`tests/script/` 和 `tests/text/` 各按功能分文件，README 放索引。函数名对应编号，例如 `test_PKG_01`。文本用例写清前提、步骤和预期。

## 测试时

- **脚本层**复用现有工具核对应用包字段、签名、架构和资源。
- **AI 层**按文本步骤实测。按键前确认前台应用、窗口和用例所需的选区状态。用测试标签页核对数量、地址、历史和窗口归属，并与同一状态下的原生行为对照。脚本异常时在相同条件下定位第一处差异，修复后覆盖原触发条件再确认结果。
- **人类层**处理确需本人完成的物理按键、系统授权、重新登录或预期取舍。AI 先完成可执行的检查，给出已取得的证据和剩余操作。条件不足时继续其他独立用例。

## 测试后

- **结果**按编号记录前提、实际结果和证据，标明通过、失败或未验证。实机、合成事件、状态图标和只读检查分别记录。物理键与系统集成按实机结果判定。
- **部分覆盖**按实际测到的组合记录结果，注明剩余组合和原因。所有规定组合都通过时，才将整条用例记为通过。任一组合失败则记失败。已测组合均通过且有组合未测时，整条记「未验证（部分通过）」。例如 `CHR-04` 只测了简体中文菜单的普通窗口，就单独记录这一组合，列出无痕窗口及其他语言的未测组合。
- **清理**在完成、失败或中断时关闭本轮窗口、标签页和测试实例，恢复前台应用、键盘模式、原有映射及本轮变更的偏好或授权。强退用例先完成下一次启动清理。记录本轮启动的进程 ID，结束时停止并确认退出。将构建副本、日志、截图和临时文件移入系统废纸篓，保留仓库用例和样本。
- **维护**在用户明确要求发布时，把本版已验证的新行为、复现样本和曾漏测的触发条件补入用例库。更新行为、更换样本或切换执行方式时沿用原编号。
