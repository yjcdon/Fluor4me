# Fluor4me 2.6.0 技术方案

2.6.0 精简从原版 Fluor 继承的更新、通知和安装提示。用户仍可给指定应用设置功能键模式，在 Chrome 网页中按内置键盘的 F4 搜索选中文字。本文以 2.5.2 为对照，记录 2.6.0 的实现范围和验收标准。开发步骤见[任务清单](任务清单.md)，验收见[测试用例](测试用例.md)。

## 平台支持范围

2.6.0 的 Release 应用面向 Apple Silicon Mac，最低运行系统为 **macOS 14.0**。构建脚本从 `Fluor/Info.plist` 的 `LSMinimumSystemVersion` 读取最低版本，并传给 `swiftc`。Debug 和 Release 的应用包与二进制使用同一版本值。

可使用较新的 macOS SDK 构建。高于 macOS 14 的 API 按实际版本进入对应分支，例如 macOS 27 的菜单栏设置。验收既检查产物声明的最低版本，也在 macOS 14 真机验证规则切换和 Chrome F4 搜索。[构建脚本](../../scripts/build-app.py) · [应用元数据](../../Fluor/Info.plist)

## 两项核心行为

| 场景 | 2.6.0 的行为约定 |
| --- | --- |
| 切换到已配置的应用 | 在自动切换模式下，按该应用的规则使用标准 F1–F12 或亮度、音量等媒体键。设为「与默认模式相同」时使用全局默认值。菜单、规则编辑器和运行中的应用共用已保存的规则。 |
| 切换到 Google Chrome | 沿用 2.5.2 的优先级。Chrome 在前台时使用媒体键模式，即使已为 Chrome 保存了标准功能键规则。F4 在普通网页中搜索选中文字，F1/F2 和音量键仍可用。离开 Chrome 后撤销 F4 映射，按当前切换方式处理下一应用。 |
| 手动操作和恢复 | 保留单按 Fn 的全局及逐应用切换、暂停与恢复、退出时的模式设置、登录启动和菜单栏显隐。正常退出、会话离开及异常退出后重启，沿用现有映射清理流程。 |

规则由 `AppManager` 保存，`BehaviorController` 根据前台应用选择模式，`FKeyManager` 设置键盘。Chrome 专用映射和通过辅助功能读取选区由 `ChromeF4Shortcut` 负责。本次涉及的执行位置包括启动、Fn 手动变更后的通知、暂停和恢复、模式变化后的图标刷新。[规则与模式切换](../../Fluor/Controllers/BehaviorController.swift) · [Chrome 搜索和映射恢复](../../Fluor/Misc/ChromeF4Shortcut.swift)

## 升级与构建

- 使用现有 Bundle ID `io.github.yjcdon.Fluor4me` 和规则存储格式。沿用已有偏好迁移，保留用户的逐应用规则、触发方式、退出偏好及 F4 异常恢复标记。旧通知、更新、图标样式的偏好可留在磁盘，新版忽略即可。避免清空整个偏好域。[启动与迁移](../../Fluor/Misc/AppDelegate.swift)
- AppDelegate 直接启动 NSApplication，Swift 创建菜单、设置、「关于」和两个应用列表。现有 AppManager、键盘控制器和 Chrome F4 映射继续处理原先的业务行为。保留应用标识、已保存规则、授权提示和窗口位置标识。启动默认模式设置读取并写入原有 `DefaultKeyboardMode`。
- Command Line Tools 编译 Swift 源码和锁定版本的 DefaultsWrapper，将原应用图标转换为 `.icns` 并随三种语言的字符串表放入应用包。运行时由 AppKit 提供界面符号。构建脚本完成签名和签名验证。CLI 包成功后清理已被替代的 Storyboard、XIB、专属视图和 Xcode 工程。
- Debug 和 Release 的版本、构建号和最低系统取自同一份 Info.plist。构建只读这些值，发版时由发布人调整构建号。

## 开发基线与界面结果

源码基线为 `main` 的 `8dadc97`，对应用户可见版本 2.5.2。以下类名、偏好键和 Interface Builder 对象标识均取自该版本。接手时若源码已演进，优先沿业务入口核对调用方。

- 用户打开菜单后，仍可设置默认模式、调整当前应用、管理规则、浏览运行中的应用、切换登录启动、暂停或退出。菜单栏图标沿用系统的显隐管理。
- 偏好设置最终只有「通用」和「高级」。通用页提供登录启动、启动默认模式和退出恢复设置。高级页提供显示全部运行进程、隐藏切换方式、Fn 短按时长。「隐藏切换方式」现有动作还会把切换方式设为自动，删除外观选项时应保留该动作。
- 「关于」保留应用名、实际版本与构建号、署名和一个 GitHub 入口，目标为 `https://github.com/yjcdon/Fluor4me`。安装说明中的版本下载入口使用该仓库的 Releases。保留原始版权和许可证。

## 规则、物理按键与存储

| 状态所有者 | 值及业务含义 | 开发约束 |
| --- | --- | --- |
| AppManager 的 AppRules | 每条规则持久化为 id（应用标识）、path（应用路径）、behavior（规则）。规则枚举 0 为跟随默认，1 为媒体键，2 为标准功能键。 | 读取历史记录时按原枚举解释；界面设回跟随默认时沿用删除显式规则的路径。列表和菜单均通过现有规则写入及广播流程同步。 |
| DefaultKeyboardMode / FKeyMode | 默认键盘模式的 0 为媒体键、1 为标准功能键。这套数值与上述应用规则枚举含义不同。 | 由 keyboardStateFor 解析规则，再向 FKeyManager 传入键盘模式。图标跟随已生效的键盘模式。 |
| DefaultSwitchMethod | 0 为随前台应用切换，1 为随前台应用切换且允许短按 Fn 修改当前应用，2 为短按 Fn 切换全局模式。 | 后两种模式都会读取短按时限。混合模式把变更写入当前应用规则，全局模式更新默认值。清理 Fn 操作后的通知时要保留这两种写入。 |
| BehaviorController | onLaunchKeyboardMode 记录启动原值，currentMode 记录按规则或手动操作请求的模式，appliedKeyboardMode 记录已生效的模式。 | 在 Chrome 中请求值可能与生效值不同。菜单栏按生效值绘制，保存的应用规则仍按用户选择显示。 |
| 系统辅助功能授权 | ChromeF4Shortcut 在授权后安装事件监听并读取 Chrome 页面的选区。启动时提示标志只用于控制应用的提示次数。 | 运行时以 AXIsProcessTrusted 的实际结果为准。普通应用的自动模式切换与 Fn 监听、Chrome 搜索分别验证。 |

自动切换的调用顺序是前台应用变化 → 按应用标识查规则 → 解析为请求模式 → 判断 Chrome 优先级 → 写入键盘 → 显示生效模式。应用标识优先用 bundle identifier，缺失时按现有可执行文件名处理。三个编辑入口的变化通过内部事件同步；实现时保留事件的来源字段，避免重复处理自身写入。[规则编码](../../Fluor/Models/Items.swift) · [枚举](../../Fluor/Models/Enums.swift) · [规则存取](../../Fluor/Models/AppManager.swift)

## Chrome 搜索与恢复边界

1. Chrome（普通版标识 `com.google.Chrome`）成为前台时，先应用媒体键模式，再在受支持的内置键盘上尝试追加 F4 的映射。已有相同来源键的用户映射时让其优先。缺少辅助功能授权或未找到对应内置键盘时，跳过专用映射。
2. 映射把 F4 发出的 Spotlight 搜索键转换成 F18。事件监听只在映射有效且 Chrome 处于前台时接收这个事件。一次非自动重复的按下提交一次查词。辅助功能读取在独立队列执行，打开搜索结果前再次核对前台 Chrome 进程。
3. 搜索对象为当前网页里的选区。过滤安全输入框、地址栏等浏览器界面及首尾空白。有效文本作为 Google 搜索参数 q，保留中文与字面加号。在 Chrome 打开新标签页即为成功。
4. 离开 Chrome 时移除本应用加上的那一条映射，其他映射继续存在。暂停和会话休眠时恢复启动键盘模式。正常退出总会先清理 F4，整排功能键则按退出偏好决定。异常退出后，下次启动先读 ChromeF4MappingNeedsCleanup（待清理标志），再根据新的前台应用决定是否重新安装。

## 升级数据及回退

2.5.2 与计划中的 2.6.0 共用偏好域。升级后先沿用 migratePreferences，再加载规则。已有从旧标识 com.yjcdon.Fluor4me 迁移的逻辑只补缺少的键，并保留现有迁移标记和排除项。此次版本无需新增数据迁移。旧图标、通知和自动更新选择留在原偏好域即可；它们不会决定 2.6.0 的行为。

退出时先移除搜索映射。ResetModeOnQuit 关闭时沿用最后的键盘模式；开启且 SameStateAsBeforeStartup 开启时恢复启动值；开启且选择指定模式时应用 OnQuitState。故障回退可正常退出候选包，再在同一测试账户启动 2.5.2，以原规则格式核对 A、B 两条规则。若应用签名变化导致 macOS 要求重新授权，先记录授权状态，再验证搜索。不可用清空所有偏好的方式掩盖升级问题。
