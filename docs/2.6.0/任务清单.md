# Fluor4me 2.6.0 任务清单

下表记录实现与验收进度。每完成一个独立功能，完成该功能可执行的检查后立即做一次本地提交，再推进下一项。按[技术方案](技术方案.md)限定改动范围，验收编号对应[测试用例](测试用例.md)。

本版本目标还包括在只安装 macOS Command Line Tools 的 Apple Silicon Mac 上，从源码构建并签名完整的 Fluor4me.app。菜单、设置、规则编辑和运行中的应用使用 Swift 创建的原生 AppKit 界面。

## 实施顺序及检查点

先在 2.5.2 记录 A → Chrome → A 的实际按键结果及一组已存规则。实施时把任务 1、4、5 对偏好窗口的编辑放在一起，对照保留页核对一次绑定；任务 2、3 一起编辑现有「关于」窗口。开发中按改动运行对应的用例，任务 8 在最终候选包集中验收。

### 1. 更新器

- [x] 从偏好窗口的 tab 列表和子控制器关系中移除 updates_tab。移除通用页中单独实例化的更新器，同时检查手动检查按钮、上次检查时间、自动下载和自动检查绑定。
- [x] 从工程的 Frameworks、Embed Frameworks 和文件引用中移除 Sparkle；从 Copy Bundle Resources 删除 dsa_pub.pem。删除 Info.plist 的 SUFeedURL、SUPublicDSAKeyFile 和 SUPublicEDKey。
- [x] 调整 README 的源码构建步骤及相关专属配置。构建产物验证使用 C01；反复打开偏好窗口验证使用 C02。只隐藏「更新」标签无法满足这项任务。

### 2–3. 发布说明和「关于」

- [x] 将 AboutViewController 接入「设置」，移除 AboutWindowController 和对应的菜单动作。移除日志入口、两个 ReleaseNotes 控制器、专属 Release 模型和 ReleaseNotes.rtf。核对 LastRunVersion 的剩余引用。
- [x] 沿用 getBundleVersion()、原版本标签及 goToGithub(_:) 按钮动作，仅将 FLGithubURL 改为当前仓库。清理网页、Twitter、支持按钮相应的 IBOutlet、IBAction、约束和专属图像，核对保留控件的定位与点击范围。
- [x] 清理旧「关于」界面对应的翻译和控件引用。复核项目链接的实际目标及当前版本文本，见 C03。

### 4. 系统横幅与授权流程

- [x] 在 AppDelegate 启动路径去掉 askUserAtLaunch，保留偏好迁移、辅助功能检查及主菜单加载。设置窗口去掉 notification_tab、嵌入场景、授权引导场景和关联跳转。
- [x] 清理 UserNotificationHelper、UserNotificationEnablementViewController、Enums.swift 中通知选项集合、AppManager 中专属偏好和对应本地化文案。核对旧通知 API 与新版 UserNotifications 调用均已退出目标。旧偏好值可自然留存，沿用原有 migratePreferences。
- [x] 按技术方案逐个核对三个通知触点，保留 Fn 监听、规则写入、内部通知及图标刷新。分别用 C04、C08、C09、C12 验证反馈、同步和权限。

### 5. 菜单栏图标

- [x] 从高级页移除 UseLightIcon 绑定及专属布局。核对 awakeFromNib、deinit、quitApplication 里的偏好监听注册和注销，保留窗口、菜单等其他订阅。
- [x] 在已有 showKeyboardMode 中按媒体键、功能键和暂停状态使用 2.5.2 的原菜单栏模板图。启动及恢复时取现有 appliedKeyboardMode 刷新。键盘设置在模式变化时写入。
- [x] 对照资源名检查主菜单、Storyboard 和 Swift 的全部引用后，清理落单资源。用 C05 和 C18 验证状态刷新与菜单栏显隐。
